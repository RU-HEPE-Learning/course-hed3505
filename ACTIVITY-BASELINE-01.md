# HED3505 Activity Baseline — Mobile-First Progressive Modules

Status: **APPROVED ACTIVITY DESIGN BASELINE**

## Canonical interaction pattern

Every module uses:

**Prompt → Tap → Reveal → Discuss → Decide → Save**

## Progressive learning architecture

### Module 1
**Problem → Indicator**  
Artifact: **WS1 Assessment Planning**

### Module 2
**Indicator → Instrument**  
Artifact: **WS2 Instrument Blueprint**

### Module 3
**Content Validity → IOC → Reliability → Revision Decision**  
Artifact: **WS3 Instrument Quality Record**

### Module 4
**Data → Interpretation → Decision**  
Artifact: **WS4 Interpretation & Decision Matrix**

### Module 5
**Integrated Evidence → Evaluation Plan**  
Artifact: **WS5 Integrated Evaluation Plan**

## Progressive portfolio

**WS1 → WS2 → WS3 → WS4 → WS5**

Each module must build on prior evidence instead of restarting from zero.

## Evidence constraints

- Master case: **โรงเรียนอรุณพัฒนา**
- Do not add new school facts outside the approved baseline.
- Simulated/instructional data used for IOC or reliability must be explicitly labeled as simulated/instructional.
- Do not represent simulated data as real school data.
- Preserve uncertainty where evidence is incomplete or contradictory.
- Human academic judgment remains authoritative.

## Design constraint for future activity development

Future refinements of Modules 2–5 must preserve the Module 1 learning-experience architecture:
- short mobile interactions;
- learner decision-making;
- reveal and discussion;
- evidence-based justification;
- saved learning artifact;
- explicit bridge to the next module.

This document supersedes the previous topic sequence that treated the five weeks as unrelated standalone activities.
