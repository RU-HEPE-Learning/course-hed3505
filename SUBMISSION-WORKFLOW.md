# HED3505 Submission Workflow

## Purpose

Provide one tool-independent submission model that works after GitHub Classroom and can support private student repositories.

## Canonical flow

```
Instructor releases activity
        ↓
Student opens weekly package
        ↓
Student completes matching assignment
        ↓
Student checks evidence requirements
        ↓
Student saves artifact + evidence + reflection
        ↓
Student commits/submits to designated private location
        ↓
Structural check (optional)
        ↓
Instructor reviews with rubric
        ↓
Feedback returned
        ↓
Student revises if required
        ↓
Final evidence retained in portfolio
```

## Submission states

| State | Meaning |
|---|---|
| NOT_STARTED | activity not yet begun |
| IN_PROGRESS | student is working |
| SUBMITTED | required artifact/evidence submitted |
| REVIEWED | instructor feedback provided |
| REVISION_REQUESTED | changes requested |
| COMPLETE | final evidence accepted for course portfolio |

These are workflow states only and are **not grades**.

## Student submission package

A submission may contain only items required by the approved assignment:
- task artifact;
- requested supporting evidence;
- reflection;
- other explicitly approved files.

Do not add unnecessary personal information.

## Private-by-default rule

Student-specific repositories or portfolio spaces should be private by default. Public course repositories contain learning materials and de-identified instructional evidence only.

## Feedback

Instructor feedback may be recorded using repository comments, pull-request review, or an approved portfolio feedback record.

No single GitHub feature is mandatory; the academic requirement is a traceable connection between:
**task → evidence → feedback → final portfolio artifact**.

## Official grading boundary

GitHub supports evidence and feedback workflow. Official scores/grades remain outside GitHub during this pilot unless a later explicit governance decision authorizes otherwise.
